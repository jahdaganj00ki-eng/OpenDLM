# OpenDLM

A free download manager for Windows. Free as in **permanently free**: there is no
trial, no nag screen, no licence key, no feature held back, and nothing to buy.
OpenDLM is MIT licensed, so you can read it, change it and ship it.

**Download:** [github.com/jahdaganj00ki-eng/OpenDLM/releases](https://github.com/jahdaganj00ki-eng/OpenDLM/releases)

OpenDLM downloads files the way a proper download manager should: it splits a file
into several byte ranges, fetches them over parallel connections, writes them
straight into their final position in the destination file, and can resume after a
pause, a dropped connection or a reboot.

## Independence and licensing

OpenDLM is an **independent, from-scratch project**. It is not affiliated with,
endorsed by, or derived from any commercial download manager.

Nothing in this repository is copied from another product. That means:

- no third-party binaries, DLLs, executables or installers;
- no third-party icons, bitmap toolbars or dialog artwork;
- no third-party translation or string tables;
- no reverse-engineering of, and no patching of, anybody else's software.

Every feature here is reimplemented from public behaviour, and every asset is
generated by this repository's own code: `scripts/make-icons.mjs` draws the browser
extension icons, and `AppIcons` draws the window and notification-area icon at
runtime with GDI+.

The reference program installed on this machine was analysed by **reading its
registry settings** under `HKCU\Software\DownloadManager` — 80 top-level values and
206 subkeys, which is that product's complete settings surface. No file of that
installation was executed, decompiled or copied.

One finding worth stating: **this installation does have a dark mode.** It is a
menu item — `34042 = "Dunkelmodus"` in the language file — and id `21206` explains
that IDM uses the dark mode when it is enabled in the Windows settings, with id
`21205` noting that a restart is required. It is absent from the registry, which is
why a registry-only search concludes the feature does not exist. OpenDLM offers the
same three choices, applies them without a restart, and follows Windows by default.

## Highlights

**Download engine**

- Multi-connection segmented downloading (1 to 32 connections per file).
- Resume that survives pauses, dropped connections and application restarts, with
  `ETag` / `Last-Modified` / size validation so a changed remote file is re-fetched
  instead of resumed into corruption.
- Automatic fallback to a single connection when a server does not honour byte ranges.
- Per-segment retry with backoff, and whole-download auto-retry for transient failures.
- Global bandwidth limiting (token bucket) applied across all connections.
- Preallocated destination files, so completing a multi-gigabyte download is an
  instant rename rather than a copy.
- Optional MD5 and SHA-1 checksums, and optional size verification.

**Organisation**

- Named queues with scheduled windows, including windows that run past midnight.
- Category tree (Video, Music, Programs, Documents, Compressed, Other) driven by a
  file-type table you can edit.
- Site logins for protected servers, with passwords encrypted at rest via Windows
  DPAPI (no extra package required).

**Integration**

- Manifest V3 browser extension for Chrome, Edge, Brave, Opera and Vivaldi.
- Native messaging host so the extension can hand downloads to the desktop app.
- Context-menu entries, link interception, media detection, and a configurable
  modifier key to force or bypass takeover.
- Command line interface for scripting and for browser `.url` handlers.

**Privacy**

OpenDLM has no telemetry and no analytics. It makes network requests only for the
downloads you ask it to make. `OPEN_DLM_HOME` puts every byte of state in a folder
you choose, so portable and forensic-friendly use is supported.

- Windows 10 or 11 (x64).

## Building

**Builds happen in GitHub Actions, not on your workstation.** That is a deliberate
policy for this project: the artefacts that people download are produced by a clean,
reproducible runner, and the build is auditable in the Actions tab.

- Every push to `main` and every pull request runs the
  [**Build** workflow](.github/workflows/build.yml): restore, compile, run the engine
  test suite, **run a self test against the published application itself**, and
  validate the browser extension.
- Pushing a tag such as `v0.1.0` runs the
  [**Release** workflow](.github/workflows/release.yml), which produces the framework
  dependent and self-contained archives plus the extension zip, writes `SHA256SUMS.txt`,
  and attaches everything to a GitHub Release.

### Why the build also runs the application

A WPF window compiles happily with a missing resource key or a broken template and
only fails when the window is first shown, so a green build says very little about
the interface. `OpenDLM.exe --selftest` therefore constructs the engine, applies all
three themes, verifies every resource key the windows depend on, and then shows each
window. That step has already earned its place: it is what caught invariant
globalization killing the application on startup, and a string being assigned to
`Path.Data`.

To build from a checkout anyway — for local development — there is exactly one entry
point, and CI calls the same script so the two cannot drift:

```powershell
./build.ps1                 # restore, build, test
./build.ps1 -Publish        # also stage a runnable bundle in artifacts/OpenDLM
./build.ps1 -Publish -SelfContained
```

## Installing

1. Download `OpenDLM-<version>-win-x64.zip` (or the self-contained archive) from the
   Releases page and unzip it anywhere.
2. Run `OpenDLM.exe`.
3. To wire up your browser, load the extension and register the native messaging host:

```powershell
# 1. Load the extension: chrome://extensions -> Developer mode -> Load unpacked -> the
#    "extension" folder from the archive. Note the ID shown on the card.
# 2. Register the host with that ID:
./scripts/register-native-host.ps1 -ExtensionId <the-id-from-chrome>
```

See [`docs/EXTENSION.md`](docs/EXTENSION.md) for the details and for troubleshooting.

## Command line

```
OpenDLM -d https://example.com/big.iso
OpenDLM -d https://example.com/a.zip -p D:\Downloads -f archive.zip -c 16
OpenDLM --batch urls.txt --queue
OpenDLM -d https://example.com/file.pdf -s -x     # silent, exit when finished
```

Run `OpenDLM --help` for the full list. Both `-d` and `/d` styles are accepted.

## Architecture in one paragraph

`OpenDLM.Core` is a UI-free library: it probes a URL to learn its size and whether it
supports byte ranges, splits the file into segments, opens one HTTP range request per
segment, and writes each stream at its own offset in the preallocated partial file
using `RandomAccess` so no locking or seek races are possible. Segment positions are
flushed to a `.opendlm` sidecar beside the file, which is what makes resume reliable.
The WPF application owns the visual list and marshals engine events onto the UI
thread; the native messaging host is a thin, stateless bridge that forwards browser
requests over a `CurrentUserOnly` named pipe.

## Tests

The test suite has no external dependencies and speaks to a real HTTP server
implemented on a raw TCP socket, so it can prove the engine's actual behaviour:
byte-perfect multi-connection downloads, single-connection fallback, resume after
dropped connections, pause/resume integrity, authentication prompts, 404 handling,
category routing, checksums, bandwidth limiting and queue behaviour.

```
dotnet run --project tests/OpenDLM.Tests
```

## Portable mode

Set `OPEN_DLM_HOME` to a folder and OpenDLM keeps absolutely everything — settings,
download list, resume state, logs — inside it:

```powershell
$env:OPEN_DLM_HOME = 'E:\OpenDLM'
./OpenDLM.exe
```
